## What the brief got wrong

Facts the next brief must carry.

- **The 目 chain has no entries.** `CLAUDE.md` §5 describes 目 with 目印, 目玉, 目安, 目標, 目的 and §2 uses 目的 as a 音音 anchor. No entry in any batch contains 目. The chain row exists with an empty `entry_order`; the anchors are not in `scripts/anchors.json` because §7.8 would fail every build on them. 値 has one entry (値段) and 所 two (台所, 場所).
- **The 手 chain's "clean" rule has an exception in the data.** 手段 (しゅだん, 手 = シュ on) is in the dataset; the validator's clean-rule check flags it (WARN 17). 切手 and 新手 also have 手 in second position.
- **The status rule table leaves one string unmatched.** `variant — widespread but prescriptively contested` (施行 せこう) contains neither "widespread but contested" nor "originally non-standard" and fell to `disputed`, per the rule. The brief's "NHC changed" is a typo for "NHK changed"; both spellings are in the rule and harmless.
- **The stem rule needs two verb classes, not "remove trailing okurigana".** けし ← けす is a u-row → i-row shift, not a truncation; つけ ← つける is a truncation. The spec now states both. With them the omission check flags exactly 勝負 and 新手, as predicted.
- **The §7.5 converse check fires on three entries the brief did not anticipate:** 早速 (the source lists サッ among 早's on readings), 雨具 (the source itself says グ is the standard on reading), 縁側 (がわ is listed among 側's kun readings). Legitimate WARNs; content questions for Dan.
- **Self-correction prose is 16 fields on 11 entries** besides 音読み (the audit's count of 12 entries included 音読み). Listed in the flagged report, not rewritten.
- **The prototype's chain marks are mostly single-entry characters.** 13 of the prototype's 30 chain characters (学, 会, 出, 山, 道, 職, 役, 数, 今, 明, 代, 行, 食, 飯) are on fewer than three entries and are not in the whitelist; the migration report lists every dropped mark.
- **`DATA_SPEC.md` §1 names `data/source/prototype-entries.json`,** which does not exist; the prototype entries are extracted from the `.jsx` at consolidation time. Outside this session's authorized amendments.
- **`BUILD_PLAN.md` 0.7 still says "the six known defects"** while `CLAUDE.md` §6 lists eight (audit §7.1). Not amended (not authorized).
- **Dictionary sites are unreachable from the cloud session.** Wiktionary, Kotobank, Weblio, Wikipedia, Jisho and Kanjipedia are all blocked by the session's network proxy. The 桶 check (defect 6.5) was made through web search, whose quoted extracts of 漢字ペディア and コトバンク are what was read; recorded as such in `scripts/fixes.ts` and the migration report.
- **The Pages run needs the compact file before `npm test`.** The first push to `main` failed CI: `src/data/load.test.ts` imports the gitignored compact file, which a fresh checkout lacks. Fixed by a `pretest` script that generates it; second push green.

## Deliberate divergences

- **The compact form carries fields beyond `DATA_SPEC.md` §4.4**: `chars[].on`, `.kun`, `.note`, `contested`, `contestedNote`, `tags`. Each derives one-to-one from a canonical field and the round-trip test covers all of them; the inspection page needs them and Phase 1's Prediction Challenge will need the reading inventories. §4.4 was not in the authorized amendments, so the divergence is recorded here rather than in the spec. DO NOT REVERSE.
- **`difficulty_rationale` is not in the compact form** (§4.4 does not list it). The round-trip test reconstructs every canonical field except it and the four consolidation-only fields (`source_id`, `source_batch`, `char_count`, `has_kana`, `decomposable`).
- **Defect 6.4 was fixed in two fields of 音読み**, not one: the trap note (named) and `difficulty_rationale`, which repeats the identical wrong claim. Leaving it would keep the contradiction alive in a field the UI shows. Both patches are named and reported.
- **`reports/02-flagged.md` is generated by the validator**, not hand-written, so the WARN table can never drift from the validator's count (§9.2). The judgment flags in its §6 are a static list inside `validate.ts`, labelled as such — the audit's corrections list set the precedent.
- **`$note` on `data/chains.json`** explains the file's status in place; the schema allows it as optional.
- **A `pretest` script** (`tsx scripts/build-compact.ts`) runs before `npm test` so a fresh clone and CI pass without a prior build. DO NOT REVERSE.
- **`scripts/build-index.ts` runs inside `npm run build`** and a test asserts the committed `reports/03-index.md` equals a fresh generation, so a data change without regenerating the index fails the build.
- **The old build-time `__SOURCE_ENTRY_COUNT__` define was removed** with the hello page; `scripts/source-count.ts` stays as the one place the source file list lives (the consolidator reads it).
- **`PLAN.md` rode along in the CI-fix commit** ("Generate the compact file before tests…") rather than its own; the content is the close-out the brief asks for.
- **No `kokuji` tag on 茶畑, 申込, 辻褄, 枠組み**, no `meta`, `meal_matrix`, `color`, `number`: only the brief-mandated tags were applied; the candidates are a flag with a recommended answer.
